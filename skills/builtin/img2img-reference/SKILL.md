# 用用户的图做图生图 / 参考图

## 为什么不能直接改文件名

工作流被捕获时，`LoadImage` 节点的 `image` 输入记的是**当时那张图的文件名**
（形如 `478952ddd100baa1a543e7be0110b912c9fc2efa.jpg`），它指向 ComfyUI
`input/` 目录里的一个文件。用户这次上传的图在**我们的库**里，跟那个文件名毫无关系。

所以有两种做法，只有第一种是对的：

- ✅ 把用户这张图**放进 ComfyUI 的 input 目录**，拿到它在那边的真实文件名，再覆盖节点输入；
- ❌ 直接改写那个旧文件名 —— 那会指向一个不存在的文件，ComfyUI 会报 `invalid image file`。

**不要**因为"改不了文件名"就告诉用户做不了 —— 按下面的三步做就能真的用上。

## 三步（顺序不要调换）

1. `comfy_use_attachment(attachmentId="…")`
   - `attachmentId` 在**用户消息末尾的附件说明**里（形如 `id=att_xxx`）；没带图的轮次没有这一段。
   - 只接受**图片**附件；视频 / 音频 / 文本会被拒绝并说明原因。
   - 返回 `filename`：那就是这张图在 ComfyUI `input/` 目录里的名字，**原样使用**，不要自己改。
2. `comfy_find_workflow(query="…", includeGraph=true)`
   - 看 API 节点图里哪个节点是 `LoadImage`（`class_type` 为 `LoadImage`），记下它的**节点 id**
     和输入名（通常是 `image`）。图生图工作流往往还有一个 `denoise`/`strength` 之类的强度输入。
3. `comfy_submit(promptId=…, overrides={…})`
   - 键写成 `节点id.输入名`，例如 `{"89.image": "<第 1 步返回的 filename>"}`。
   - 想控制"改动幅度"就一起覆盖强度输入（例如 `{"89.denoise": 0.6}`）——**前提是那个节点真的有这个字段**，
     字段不存在会被直接拒绝，别硬猜。用户没说强度就先用工作流自己的默认值，别擅自大改。

## 纪律

- 覆盖参数一律按 `节点id.输入名`，**参数覆盖失败一定要如实说**，不要假装跑成功了。
- 模型看不到这张图（正文里有"以下附件未随本次请求发送"那句说明）时**照样能投放** ——
  文件在库里。但要如实告诉用户"我没看到图内容，是按你放的参考图跑的"，不要编造图里的细节。
- 产物只认 `comfy_submit` 返回的 `mediaIds`：没拿到就说没拿到，不要说"已经生成了"。
- 同一个附件重复投放会得到**同一个文件名**（名字里带附件 id 后缀），所以重跑工作流是安全的。
