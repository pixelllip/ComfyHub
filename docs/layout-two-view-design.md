# 双视图布局：镜头视图 + 俯视摆位（设计稿）

> 状态：**设计稿，未实现**（2026-11-11）。
> 3D 路线仍然搁置（[`layout-3d-design.md`](layout-3d-design.md)）；本文是它的轻量替代：
> 不做三视图、不做房间体块，只把"深度"和"朝向"补进 2D 布局。
> 现有链路（工作台出模板、画布改框、提交回工作台、核对模板）见
> [`layout-workspace-design.md`](layout-workspace-design.md)。

## 0. 结论

两个 2D 视图就够，但**它们必须是同一个场景的两张投影**，不是两张各自独立的框：

- **镜头视图**：成图的那一张。管左右位置、画面占比、谁的哪一部分被裁掉。
- **俯视摆位**：不进成图。管前后深度、朝向、谁在地面 / 台阶 / 台口之下。

平视机位（pitch ≈ 0）下，三个轴正好分完：

| 方向 | 镜头视图 | 俯视图 |
| --- | --- | --- |
| 左右 X | 水平位置 | 水平位置 |
| 上下 Y | **离地高度** | — |
| 前后 Z | — | **深度** |

镜头视图的竖直方向本身就是立面：框的底边是接地位置，顶边是物体高度。
三视图里那张侧立面在这里是多余的。**代价是它只在平视时成立**；仰拍 / 俯拍会让
竖直方向同时混进高度与深度，那时才需要第三张图（本设计不做）。

## 1. 目标与非目标

**目标**

1. 模型拿到的不是"几个 2D 框"，而是一段确定的**场景块**：层序、遮挡、支撑、朝向、光位。
2. 用户能在俯视图里把"合唱团在身后、站在台阶上"这种关系摆出来，而不是写进 caption 里赌模型读懂。
3. 现有出口不破：MOSS 布局 JSON 仍只吃镜头视图的轴对齐框；核对模板仍只对照镜头视图。
4. 模型仍然只写它擅长的部分（镜头视图的框、名称、描述），深度与朝向可以由用户补，
   也可以由模型先填一版粗值。

**非目标**

- 不做三视图、不做侧立面、不做房间墙角、不做体块 / 深度图（已证伪，见 `layout-translator.md`）。
- 不做任意斜面 / 非盒体。琴盖这种绕水平轴打开的平面，本设计只能记一个 `tilt` 提示，
  真正的几何留到以后。
- 不要求模型做投影。投影与反解都在后端 / 前端做，模型只读结果。
- 不改 MOSS 的 `bbox` 契约。

## 2. 场景模型

### 2.1 坐标与单位

- 世界坐标：**X 向右，Y 向上，Z 远离相机**（右手系，相机看向 +Z）。
- 相机在 `(0, eye, 0)`，平视，无 roll；主点在画面 `(0.5, horizon)`。
- 画面单位仍是 `0~1000` 归一化（与 `layout_spec.dart` 一致）；世界长度用**米**，
  只在场景块与校验里出现，不进 MOSS JSON。

### 2.2 相机

```jsonc
"shot": {
  "width": 1024,
  "height": 1024,
  "eye": 1.55,          // 视高（米）
  "fov": 50,            // 水平视场角（度）
  "horizon": 0.48,      // 地平线在画面高度的比例；0.5 = 正中
  "yaw": 0              // 机位朝向（度）；MVP 固定 0
}
```

`horizon` 用**主点偏移**实现，不是俯仰：它等价于移轴镜头，竖线仍然竖直。
真正的 pitch 留到以后；本设计假定相机水平。

### 2.3 框

```jsonc
{
  "id": "r1",
  "label": "钢琴演奏者",
  "kind": "character",
  "x": 40, "y": 120, "w": 300, "h": 700,   // 镜头视图（0~1000）
  "z": 120,                                  // 深度（0~1000，0 = 最近）
  "yaw": 15,                                 // 朝向（度，0 = 面向相机）
  "support": "floor",                        // floor / riser / table / wall
  "tilt": 0                                  // 可选：斜面提示（琴盖），不参与投影
}
```

世界位置与尺寸**不单独存**，由镜头框、`z` 和相机反解：

```
f   = (width / 2) / tan(fov / 2)          // 像素焦距
cx  = width / 2
cy  = horizon * height
Z   = Z_NEAR + (z / 1000) * (Z_FAR - Z_NEAR)   // 归一化深度 → 米
sx  = cx + f * X / Z
sy  = cy - f * (Y - eye) / Z
```

`Z_NEAR` / `Z_FAR` 是一对固定常数（建议 0.5 米与 25 米），只用来把 `0~1000`
的滑杆映射到米；它们不进 JSON，换机器也不变。这样 `z=0` 是贴着镜头，`z=1000`
是远景，用户不需要填"几米"。

反解（已知 `Z`，由屏幕点求世界点）：

```
X = (sx - cx) * Z / f
Y = eye - (sy - cy) * Z / f
```

于是：

- 框底边的世界高度 = 接地高度（`base`）；
- 框顶边减底边 = 世界高度（`h_world`）；
- 左右边 = 世界宽度（`w_world`）；
- 俯视图的脚印宽度就是 `w_world`，深度方向用户可调一个 `d`（默认 `0.6 × w_world`）。

**为什么反解而不是正解**：镜头框是用户真正在意的（构图），`z` 是用户补的（摆位）。
两者都有时，`base` / `h_world` / `w_world` 是**推导量**，不会出现第三份互相矛盾的数据。

### 2.4 光

```jsonc
"light": {
  "key": "frontLeft",   // frontLeft / frontRight / backLeft / backRight / top
  "height": 2.4,        // 主光高度（米）
  "color": "amber"
}
```

光不进投影，只进场景块与提示词自检："主光在左前方"与"合唱团正面被照亮"必须一致。
光位仍是粗档，不做灯具几何。

## 3. 两个视图

### 3.1 镜头视图

- 画现在是画布上的那一张，坐标不变。
- 编辑：拖 = 左右 X；上下 = 离地高度（`z` 固定时）；缩放 = 世界尺寸。
- 显示：框、名称、关系；可选的透视网格 / 地平线。
- 出图核对只认这一张。

### 3.2 俯视图

- 正交投影：横轴 X，纵轴 Z（近在下、远在上）。
- 每个框画成**带朝向的脚印**：宽 = `w_world`，深 = `d`，按 `yaw` 旋转；
  中心在 `(X, Z)`。
- 编辑：拖 = X / Z；旋转手柄 = `yaw`。
- 显示：地面网格、相机位置与视锥（两条射线）、台阶 / 台口的水平线。
- **不出图、不进核对模板**。

### 3.3 联动规则（唯一真源）

两个视图共享同一个 `id`，改一个，另一个重画。冲突不做自动纠正，只报警：

| 用户动作 | 改什么 | 另一个视图 |
| --- | --- | --- |
| 镜头视图里左右拖 | X | 俯视图水平移动 |
| 镜头视图里上下拖 | 接地高度（`base`） | 俯视图不变（`z` 未动） |
| 镜头视图里缩放 | 世界宽高 | 俯视图脚印跟着变 |
| 俯视图里上下拖 | `z` | 镜头视图的框按投影重新算位置与大小 |
| 俯视图里左右拖 | X | 镜头视图水平移动 |
| 俯视图里旋转 | `yaw` | 镜头视图的可见宽度变化（`w·|cos| + d·|sin|`） |

**P0 的俯视图只读**：`z` / `yaw` 在检查器里调，镜头框**不自动重投影**，
只把"这个框的深度与画面高度对不上"记成警告。
**P1 让俯视图可编辑，先做软联动**：拖 `z` / 转 `yaw` 时镜头框仍不自动改，只报警；
**P2 再做自动重投影**。

## 4. 场景块（给模型的事实）

模型不读两张 2D 图，读后端算好的这一段：

```text
镜头：平视，视高 1.55 米，水平视场 50°，地平线在画面 48%。
光：主光在左前方，暖琥珀；环境是冷蓝灰。
层序（由近到远）：
1. 钢琴演奏者：前景，落地，约 1.2 米远，面向琴键，头略向右回。
2. 三角钢琴：前景右侧，落地，琴盖朝右后方打开。
3. 合唱团：中景，站在 0.4 米高的台阶上，六人一排，面向相机。
4. 观众：背景，低于舞台，背对镜头，只见轮廓。
遮挡：演奏者挡住合唱团左端；琴盖挡住合唱团右侧的一部分。
```

这段由**投影与排序**生成，不靠模型猜：

- 层序：按 `z` 排序，分成前景 / 中景 / 背景三档；
- 遮挡：镜头框相交 + `z` 更近的一方挡；
- 支撑：`base` 与 `support` 一起说"落地 / 站在台阶上 / 低于台口"；
- 朝向：`yaw` 映射成"面向相机 / 侧身 / 背对"；
- 尺寸：用世界宽高与距离给"约占画面多少"，不用像素。

模型拿到的工具正文 = 场景块 + 镜头视图框表。俯视图的原始 JSON **不发给模型**，
避免它把两张图当成两个构图去同时满足。

## 5. 与现有链路的关系

| 环节 | 现在 | 双视图之后 |
| --- | --- | --- |
| `layout_propose` | 只收镜头框 | 收镜头框 + 可选 `z` / `yaw`；缺 `z` 时按画面底边估一版并在 `issues` 里说明 |
| 核对模板 | 1 个模板，只有镜头框 | 仍只有镜头框；俯视图**不进** `layoutTemplates` |
| 提交闸门 | 按提示词原文比对 | 不变 |
| `LayoutResubmit` | 散文 + spec JSON | 散文 + 场景块 + spec JSON；俯视图数据可带，但标注 `view: "plan"` |
| MOSS JSON | 镜头框直接转像素 | 不变；`yaw ≠ 0` 时按投影后的外接矩形导出，并记一条"旋转框有损" |
| 画布译者 | 一个框一段 | 按场景块的层序组织段落；仍然是"一个框一段"，校验器不用改 |

**为什么俯视图不进核对模板**：核对是拿产物和"成图应该是什么样"比。俯视图不是成图，
放进去模型会试图同时满足两张构图。俯视图只用于**写提示词之前**把空间摆对。

## 6. 校验（确定性，不靠模型）

1. **投影一致性**：同一框的 `z` 与镜头框底边必须满足
   `base = eye - (sy_bottom - cy) * Z / f`。`support=floor` 时 `base` 应接近 0；
   否则要么它站在东西上，要么 `z` 填错了。P0 先做警告。
2. **遮挡与深度**：`relation=front` 的框，`z` 必须比被挡的框小。
3. **台阶 / 台口**：`support=riser` 的框 `base > 0`；`support=floor` 且 `base < -0.05`
   的框必须落在"台口以下"的区域，否则报警。
4. **地平线**：`base = 0` 的框，底边必须落在该 `z` 的地面线上（`cy + f·eye/Z`）。
5. **光位**：`light.key=back*` 时提示词里出现"正面被照亮"就冲突（提示，不硬拦）。
6. **yaw 与 footprint**：俯视图里两个脚印大面积重叠、又没有前后关系时报警
   （与现有"重叠却没标谁挡谁"同一条纪律）。

校验结果进 `issues`，跟现有的夹边 / 清关系共用同一个出口。

## 7. 迁移与兼容

- `v: 2` 只在出现 `z` / `yaw` 时写入；`v: 1` 仍然能读。
- 缺 `z` 的框按"画面底边越高越远"估一版：`z = 1000 - clamp(sy_bottom)`，并记 `issues`。
  这是粗估，只为了让旧文件打开时俯视图不是空的。
- 缺 `yaw` → 0（面向相机）；缺 `support` → `floor`。
- 布局库、回传消息、`tool_result` 都要能读旧形状（`LayoutSpec.fromJson` 已经刻意宽容，
  新增字段继续走"认不出回默认"）。
- **不要**把 `z` 写进 MOSS JSON；不要改 `bbox_coord_space`。

## 8. 界面

- 桌面：左右分栏（镜头视图大、俯视图小），或上下两个标签页；选中一个框，两边同时高亮。
- 窄屏（< 900）：只显示镜头视图；俯视图做成弹层，不占常驻空间。
- 俯视图控件：网格、相机标记与视锥、台阶线、旋转手柄；相机面板（视高 / 视场 / 地平线）。
- 检查器：`z`、`yaw`、`support`、`tilt`；`base` / `h_world` / `w_world` 只读显示。
- 文案遵守 `AGENTS.md` §6.2：说"前后 / 台阶 / 台口"，不说 `Z`、`FOV`、`principal point`。

## 9. 分期

| 阶段 | 内容 | 估时 |
| --- | --- | --- |
| **P0** | 数据模型 + 投影/反解 + 只读俯视图 + 场景块 + 校验 1/2/3 + 旧文件迁移 | 3~5 天 |
| **P1** | 俯视图可编辑（拖 / 旋转）+ 软联动 + 相机面板 + 检查器 | 1~2 周 |
| **P2** | 自动重投影（改 `z` 后镜头框跟着变）+ 光位校验 + `tilt` | 1 周 |
| **P3**（可选） | 斜面 / 平面图元（琴盖）、镜面平面、MOSS 旋转框的精确导出 | 按需 |

P0 结束就能回答"深度和接地是否解决了三栏拼贴"；P1 才让用户真的"画两个视图"。

## 10. 验收

用这张图做端到端用例：

- 钢琴演奏者：前景、`support=floor`、`z` 最小、`yaw` 略朝琴键；
- 合唱团：中景、`support=riser`、`base > 0`、`yaw≈0`（面向相机）、六人一个框；
- 三角钢琴：前景右侧、`support=floor`、`tilt` 提示琴盖；
- 观众：背景、`z` 最大、`base < 0`（台口以下）、一个框；
- 灯：`light.key=frontLeft`、高度高于人物。

断言：

1. 场景块的层序是"演奏者 / 钢琴 → 合唱团 → 观众"，不是"左 / 中 / 右"；
2. 遮挡只出现"演奏者挡合唱团""琴盖挡合唱团右侧"两条，不出现"中缝"；
3. 俯视图里合唱团在演奏者后方，且脚印在台阶线上；
4. 提示词里不再出现"the middle band / the gap between / the edge of the stage"；
5. 320 / 360 宽下镜头视图不溢出，俯视图在弹层里。

投影与反解的单元测试：

- 已知相机 + 已知 3D 框 → 镜头框（golden 数值）；
- 镜头框 + `z` → 世界宽高（往返一致，误差 < 0.5%）；
- `yaw=90°` 的脚印取外接矩形后与投影结果一致。

## 11. 风险

1. **模型写不好 `z`**。所以 `z` 是可选的，缺了按底边估；模型只负责镜头视图。
2. **平视假设**。仰拍 / 俯拍会让"镜头视图 = 立面"失效；本设计明确不支持，
   需要时再上 pitch + 第三视图。
3. **联动歧义**。同一个框在两个视图里都能改，必须有明确的轴分工（§3.3）；
   否则用户改一处、另一处莫名变化。
4. **MOSS 只吃轴对齐框**。`yaw` 只能进俯视图与场景块，导出必须取外接矩形并如实记账。
5. **斜面表达不了**。琴盖、屏幕、翻开的书仍是 `tilt` 提示；不要用"盒子旋转"假装解决。
6. **性能**。俯视图每帧重画所有脚印；框上限仍是 8 个，问题不大，但要用 `RepaintBoundary`。

## 12. 开放问题

1. `z` 由模型先填一版，还是只由用户填？建议模型可填、可缺省，缺省按底边估。
2. 俯视图是画布的第二个标签页，还是永远并排？建议宽屏并排、窄屏弹层。
3. 台阶 / 台口是**场景级**的线（一条 `stage` 高度线），还是每个框自己的 `base`？
   建议两者都要：场景一条基准线，框可以覆盖。
4. `yaw` 的 0 度约定：面向相机，还是面向 +Z？建议面向相机（用户直觉）。
5. 俯视图要不要显示相机视锥？建议显示，帮助判断"这个物体在不在画面里"。

## 13. 与三视图方案的对比

| | 两视图（本文） | 三视图 | 完整 3D（已搁置） |
| --- | --- | --- | --- |
| 能表达 | 深度、朝向、接地、台阶 | 上述 + 侧向高度关系 | 上述 + 任意相机、墙角、斜面 |
| 用户要画 | 2 张 | 3 张 | 1 张体块 + 相机 |
| 模型要写 | 镜头框（+ 可选 z） | 三张一致的框（很难） | 体块 + 相机（很难） |
| MOSS 兼容 | 好（只取镜头框） | 好 | 好 |
| 估时 | 2~3 周 | 3~4 周 | 3 周 +（搁置） |

两视图省掉的是侧视图与它的校验，不是投影核心；它和完整 3D 共用同一套
"相机 + 深度 + 投影"，所以以后要升级，P0/P1 的投影代码可以继续用。
