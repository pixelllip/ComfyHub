## 1. 判定规则（"提示词为主"的可实现形式）

### 1.1 归一化：让"自然语言"和"权重表达"等价

```
(masterpiece:1.2), 1girl   ≡   masterpiece, (1girl:1.1)
```

1. 按 `,` 与换行切段；
2. **剥权重语法**：`(x:1.2)` → `x`、`((x))` → `x`（**要处理嵌套** —— anima 系提示词大量这么写）；
3. 去转义 `\(` `\)`、去首尾空白、连续空白压一个、**大小写不敏感**；
4. **排序 + 去重**。

> 归一化后**逐元素相同**才算"同一段内容"。归一化前不等、归一化后相等 = **"同一件事的两种写法"**，
> 要在差异摘要里明说（用户点进详情最想知道的正是"这几张差在哪"）。
> 防线：`(masterpiece:1.2), 1girl` ≡ `masterpiece, (1girl:1.1)`。

### 1.2 两层判定

| 层 | 维度 | 规则 |
| --- | --- | --- |
| **第一层：提示词** | 归一化后的正 / 负提示词 | **必须相同**（主判据） |
| **第二层：固定维度** | `checkpoint`、`loras`（集合+权重）、`sampler`、`scheduler`、`width`/`height`、`kind` | **必须相同**，任一不同 → 不归组 |
| **白名单（忽略）** | **`seed`**、**`steps`**、**`cfg_scale`**、`batch_size`、`extra_params`、时间、文件名 | 用户明确：step/cfg 不是影响产物内容的主要因素；seed 不同也算同一组 |

> ✅ §9 的"阈值"问题**作废** —— 用户已定：**提示词相同就都算一组**，不再需要"相对差 ≤ 20%"那套。

### 1.3 范围

- 比较**限最近 N 个集合**（建议 N = 500），不做全表扫；
- 先比第二层（短串/数字，便宜），再算提示词归一化（贵）；
- 代价：给很旧的集合加新变体可能打散 —— 写进文档，不藏着。

## 2. 数据模型（实化）

```
media_collections(id, kind, created_at, origin)        -- origin: auto | manual
media_assets.collection_id  INTEGER NULL REFERENCES media_collections(id) ON DELETE SET NULL
```

- 入库后 `assign_collection(media_id)`：命中已有集合就挂上去，否则新建（首张 = 单成员集合）。
- **提示词行不动**：`capture_runs.prompt_id` 指向它，**合并提示词会毁掉可追溯性**（R10）。
  归组只发生在**集合**这一层。
- 同一次运行的 batch：`prompt_id` 天然相同 → 同组，不依赖相似度。

### 2.1 ❗同步契约要一起改

`media_assets` **在同步白名单里**。加 `collection_id` 必须同时处理：

| 要改的 | 位置 |
| --- | --- |
| DDL | `db/schema.sqlite.sql` |
| 迁移 | `infra/db.rs` 的 `NEW_COLUMNS` + `SCHEMA_VERSION` +1（三处一起改） |
| 同步范围 | 总纲 §3 的"同步 / 不同步"表（**建议跟随 `media_assets` 同步**，否则手机上折叠不出来） |
| 手机侧 | Android harness 的镜像表 |

### 2.2 存量回填

- 一次性后台任务：按 `created_at` 升序遍历所有 media，跑**和入库时同一份** `assign`
  （**同一份实现，不许写第二套** —— 参考工作流配方那条纪律）。
- 回填会造出大量单成员集合 → 界面上显示成普通格子。
- ❗用户"拆开/合并"的决定要落库且**不参与重算**：`origin=manual`，重算只动 `auto`。

## 3. 画廊 / 详情页

- **封面叠放**：1 张 → 单图；2 张 → 错位两层；3+ → 三层 + 右下角总数。格子尺寸不变（不许撑高，否则行高判断会飘）。
- **详情页切换**：替换当前路由；图片 ←/→；视频音频播放控件加"上一个/下一个"；只有一张时箭头**禁用**（不是隐藏）；顺序按 `created_at` 升序（= 调参先后）。

## 4. 「预设」：由提示词页改组

### 4.1 定位与能力边界（用户定）

预设 = **可复用的一段提示词 + 用途**。页面只保留：**查看 / 修改提示词 / 用途（生图·生视频·生音频）**。

`kind` 字段**已经存在**（`IMAGE`/`VIDEO`/`AUDIO`/`MIXED`）→ **不需要加列**，"用途"就是它。

### 4.2 发送模式（纯正面提示词）

❗这是**两件不同的事**，要做成两处，别糊在一起：

| 层 | 做什么 | 为什么必须在这层 |
| --- | --- | --- |
| **预设级 `negativeMode`**（用户可见的选项） | `keep`（照原样带上负面提示词）/ `strip`（**去掉负面提示词**） | 用户的原话是"让提示词发给 comfy 执行前先修改成符合用户预期的**纯正面提示词**"，这是**写提示词时的意图**，属于预设 |
| **提交时兜底** | `comfy_submit` 前用 `/object_info` 看目标工作流的 CLIP 节点**到底认不认负面输入**；认不得就**如实提示** | 模型是否支持负面是**工作流的属性**，不是预设的属性 —— 放在这里才不会漏 |

> ⚠ 不要只做下面那层、也不要只做上面那层：
> 只做兜底，用户没法表达"我就是不要负面"；只做预设级，换个工作流又失效。

### 4.3 「▶️运行」的链路（✅ 已定：送到聊天框并跳转）

```
预设卡「▶️运行」
  └─ 弹窗选目标产物类型（预设已指定 → 默认选好；没指定 → 必须选）
      └─ 用户确认
          └─ 跳转到「AI 工作台」+ 把这段提示词填进输入框（用户自己按发送）
```

- 决定：**(甲)**。**不自动起 Run** —— 零新机制，且**不产生"无人值守的提交"**。
- ❗**实现上的一个硬要求**：现在**没有跳转机制**。
  页面是 `const pages = [AiHomePage(), GalleryPage(), ...]` + `pages[_index]`，
  切页只有 HomeShell 里的 `onDestinationSelected: (i) => setState(() => _index = i)`
  （[app.dart:333-444](../lib/app.dart)）。已有的先例是受限横幅：
  `onOpenSettings: () => setState(() => _index = 4)` —— 也就是**宿主往下传回调**。
  所以做法是：**HomeShell 往下提供"切到工作台 + 注入一段文本"的入口**
  （回调 / `InheritedWidget` / 一个薄的全局 store，三选一），
  而不是让预设页自己 `Navigator.push` 一个 `AiHomePage`（那会起第二个工作台实例）。
- 提示词怎么变成一次提交：**把正文塞进消息**（推荐），不给 `comfy_submit` 加 `presetId`
  —— 加参数要动工具清单 + bump `SystemPrompt.VERSION`（R12）。


### 4.4 「存为预设」（画廊详情）

- 位置：画廊详情页提示词区（[media_detail_page.dart:532](../lib/pages/media_detail_page.dart) 那个"查看提示词"旁边）。
- 行为：把这条产物关联的提示词**复制**成一条新预设（`source=Manual`），**不就地改名**那条自动捕获的提示词。
- 理由：自动捕获的提示词行是**运行记录**，改它等于篡改台账。

### 4.5 ❗命名：界面改、后端先不改（建议）

用户现在说"预设"，之前叫"提示词"，而**后端到处都叫 prompt**：

| 层 | 现在 | 建议 |
| --- | --- | --- |
| 界面文案 | 提示词 | ✅ 改「预设」 |
| Dart 类名（`Prompt` / `PromptsPage`） | prompt | ⚠️ 可只改页面类名（`PresetsPage`），模型类先留 |
| **DB 表 / API / 同步契约 / 手机镜像表** | `prompts` / `/api/prompts` / `search_prompts` 工具名 | ❌ **本轮不改** |
| **AI 工具名** | `search_prompts` 出现在**系统提示词**里 → 改名要 bump `SystemPrompt.VERSION`，且**手机端 run-kit 要一起下发** | ❌ 本轮不改 |

也就是说，会出现"**界面上叫预设、后端叫 prompt**"的过渡期。
❗**要你点头**：接受这个过渡，还是要求一次改到底（那是"加列三处一起改 + 同步契约 + 手机镜像 + 工具改名 + 提示词版本"的一整套）？

## 7. 工作台聊天里已删除的产物

### 7.1 根因（已查到）

- `mediaIds` 落在 `ai_message_parts.json_payload`（[tools.rs:82](../server-rs/src/tools/tools.rs)），界面按它渲染产物卡（[ai_home_page.dart:2407](../lib/pages/ai_home_page.dart)）；
- 缩略图是**裸 URL**（`/api/media/{id}/thumb`），**没有存在性检查** → 删了就 4xx → `errorBuilder` 退化成"图片不可用"小图标；
- 点进详情 → `getMedia` 抛错 → 4xx 路由错误。

**所以"能看却点不进"不是设计，是一个没被处理的中间态。**

### 7.2 决定：**全留**（用户定）

- 渲染前**批量查存在性**（`/api/media?ids=…`，避免 N 次请求）；
- 已删的渲染成**灰底斜杠占位 + "产物已删除（已从画廊移除）"**，`onTap` 置空、不可点；
- ❌ **不做**"只留最近 N 个"的折叠 —— 用户明确要**幽灵墙全留**。
- 代价（写进文档，不藏着）：反复生成又反复删，产物卡会变长；分页/懒构建要顶住。

## 8. 产物删除之后：提示词 / 工作流怎么办

- 删产物是**单条** `DELETE FROM media_assets`（[media_write.rs:112](../server-rs/src/media/media_write.rs)），**不动 prompts**；
- 两个外键都是 `ON DELETE SET NULL` → 删提示词会**静静摘掉**产物的关联；
- 反向入口**已存在**：`deleteUnlinkedPrompts`（清没人用的提示词）。

**策略：孤立保留 + 显式清理。** 删产物永远不动提示词；孤立提示词只在用户显式点「一键清除未关联」时删。

**理由（最关键）**：提示词是 **AI 的工具与记忆**。`search_prompts` / `comfy_learn_workflow` /
`comfy_bind_recipe` / 角色卡全按它工作 —— 自动删掉 = 悄悄丢掉模型以前用过的事实。

**多个产物共用一套提示词**分两种：
1. **同一次运行 batch**（batch 4 出 4 条）：本来就共用一条 → 删 2 条，提示词照旧；
2. **跨次微调归一化成同一集合**：❗**不许合并提示词行** —— `capture_runs.prompt_id` 指向它，合并会毁掉可追溯链。

### 9.3 折叠的细节（建议，待确认）

## 10. 做完这些，Comfy Agent 的应对（待做项 + 理由）

> 完整分析见 [comfy-agent-integration.md](comfy-agent-integration.md)。⚠ 这不是"接官方 API"的清单 —— 官方**没有**可接的 API。

**三条硬事实**：官方本地 agent 的沙箱把"读"压得极死（凭据/整个磁盘/自身 data dir 都**永不授予**）；
附件通道**协议上不收字节**；egress 白名单里 **loopback 永不授予** → **今天不存在它调我们的通道**。

→ 对策不是接线，是**把自己做成任何 agent 都能用的那个**，然后等它开口。

## 14. 已完成部分的落地细节（步 1~3）

### 14.1 判定真源：`server-rs/src/media/collection.rs`（纯函数 + 落库两半）

- `normalize` / `group_key` / `same_group`：**纯函数**，入库与回填共用同一份实现。
- `assign` / `backfill` / `prune_if_empty` / `prune_all_empty`：落库那一半。
- `RULE_VERSION = 1`：改判定规则必须 +1（回填据此重算）。

**判定输入只有三个字段**（`Endpoint`：`kind` + 正提示词 + 负提示词）。
谁想加 `seed` / `steps` / `cfg` 进去，会先撞上 `端点的字段只有三个` 这条用例。

### 14.2 三条在真库上量出来才定的规则（**别改回去**）

1. **孤儿产物不进组**（`Assigned::Orphan`）。
   第一次回填把 **21 张互不相干的手动导入图**按"都是 IMAGE"并成了一组 —— 那不是
   "同批微调"，点进去左右翻 21 张不认识的图毫无意义。判据是提示词，没有提示词就没有
   "走向"可判，**宁可不分组**（详情页箭头禁用，退化成普通格子）。
2. **裸括号不许剥**：`(x)` / `((x))` 在 danbooru / anima 里是**加强权重**、是真实语义。
   只剥**带数字权重的括号**（`(x:1.2)`）。早期实现递归剥光所有括号 = 改内容。
3. **转义逗号不切段**：`a\,b` 是一段。先切段再解转义会把 `a\,b` 劈成两段，
   与真的 `a, b` 撞成同一个 key（**假分组，不报错**）。

### 14.3 拼 key 用长度前缀，不用分隔符

归一化后的片段**可能含 ASCII 控制字符**（用户粘贴进来的），所以不能拿控制字符当分隔符 ——
`["a", "b\x1fc"]` 与 `["a\x1fb", "c"]` 会拼出同一个 key。
现在是 `len ⊗ "+" len2 0x1F 片段 ⊗ …`，消除歧义且不用防转义。防线用例：`片段切分不同不会拼出同一个key`。

### 14.4 删产物要带走空集合

`media_assets.collection_id` 是 `ON DELETE SET NULL`，**删产物不会带走集合行** ——
少了 `prune_if_empty` 会有两个后果：① "删到 0 张还留一个点不开的空格子"；
② 集合行**永久累积**（还会跟着同步到手机）。启动时另跑一次 `prune_all_empty` 收拾历史残留。

### 14.5 顺手修掉的一个自测脚本 bug

`scripts/e2e-capture-test.ps1` 的 `Check()` 里 `$script:Checks++` **缩进错位掉进了 `else`**，
于是**只有失败才计数** → 全绿时结尾 `if ($script:Checks -le 0)` 报"一项检查都没跑" → `exit 1`。
表现是"这套自测永远红，而且看不出红在哪"。另外三个 e2e 脚本没有这个问题（已逐个核对）。

### 15.2 三条在实现里踩到/定下来的规矩

1. **判"认不认负面"不能看"图里有没有 CLIPTextEncode"** —— 每个工作流都有一个（正面那一个）。
   判据必须落在"**采样器的 `negative` 接没接线**"上，而且**拿不到 `/object_info` 就回 `None`**（不猜）。
2. **`negativeMode` 是预设的属性，"工作流认不认负面"是工作流的属性** —— 两件事，两层做。
   只做一层会漏：只做预设级，换个工作流就失效；只做兜底，用户没法表达"我就是不要负面"。
3. **`negativeMode` 的默认值只能是 `keep`** —— 老库补列、老后端缺键时都退回 `keep`。
   退回 `positive_only` 会**悄悄丢掉用户的负面提示词**（而 turbo 之外的模型很吃负面）。

### 15.3 顺带修掉的两个真 bug

* **`favorite=1` 一直 HTTP 400** —— 「仅收藏」筛选从来就是坏的（点一下整页"加载失败 HTTP 400"）。
  根因：后端 `MediaQuery` 用 `Option<bool>`，axum 只认 `true/false`，而 Dart 发 `1/0`。
  改成宽松解析（`1/0/true/false/yes/no/on`，认不出来**当没传、绝不 400**）。
* **折叠总数漏算集合代表** —— `representative_only` 曾写成"未分组的 **或** 不是任何集合成员"，
  等于把所有集合成员全排除，于是**集合的格子在画廊里根本不出现**（`pages=1` 翻页也补不回来）。
  正确语义是"**未分组的 ∪ 每个集合里最早的那条**"。

* **图片**：预览区左右两个箭头（`onPressed == null` = **禁用**，不是隐藏）+ 顶部 `第几张 / 共几张`；
* **视频 / 音频**：箭头在**播放控件那一行**（按用户定的分开处理）—— ⚠ 这一半**还没做**，见 §17；
* 每切一条都 `NsfwStore.reveal` 新的那一条（否则"看完第 1 张，第 2 张又糊上"）。

### 16.5 ★ 切换方式：从"替换路由"改成"原地换内容"

用户第二轮反馈："**重新路由的实际行为是关闭旧窗口、打开新窗口。太奇怪了。**"

他说对了 —— `pushReplacement` 在 Flutter 里就是**旧页销毁 + 新页进场**：
`State` 被丢掉重建，页面骨架（AppBar / 布局 / 滚动位置）全部重来，视觉上就是"关一下又开"。

改成**路由始终是同一个**：

| 件 | 做法 |
| --- | --- |
| 当前看的是哪一条 | `_currentId`（`late int _currentId = widget.mediaId`）——**不再是 `widget.mediaId`** |
| 切换 | `_goTo(id)`：`setState(_currentId = id)` → `_load(showSpinner: false)` |
| 过渡 | 内容区包 `AnimatedSwitcher`，key = `_currentId`，120ms 淡入；`layoutBuilder` 把旧内容置 0 透明度，**避免图与词重影** |
| 不闪加载圈 | `_load(showSpinner: false)` —— 旧图一直显示到新数据到位（本机后端几十毫秒） |
| 换图时清提示词 | `_goTo` 里先 `_prompt = null`：不清会**短暂显示上一条的提示词**（图换了词没换，看着像串了） |
| 外部换 id | `didUpdateWidget` 跟着走（画廊重新 push 同一个路由时） |
| 后退 | 一次就回画廊（不再"翻十张要按十次"） |

**防线**：`media_detail_narrow_test.dart` 里用 **`State` 的 identity** 断言 ——
切换前后必须是**同一个 `State` 实例**。`findsOneWidget` 抓不到这个差别（换了路由之后新页面也只有一个）。
这条用例**实测过能红**：临时改回 `pushReplacement` 之后它报 `Expected: true / Actual: <false>`。
